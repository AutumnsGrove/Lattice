# Lattice integration-surface notes (Track 4) — for the agent-core planning session

All paths relative to /home/user/Lattice. Read-only exploration; nothing modified.

## 0. Headline findings
1. **`libs/grove-agent` already exists** (`@autumnsgrove/grove-agent` 0.1.0, AGPL-3.0). It is `GroveAgent extends Agent` / `GroveChatAgent extends AIChatAgent` from the **Cloudflare Agents SDK** (`agents ^0.6`, `@cloudflare/ai-chat ^0.1.5`) plus Grove logging/Signpost/observability. Files: `libs/grove-agent/src/{grove-agent,grove-chat-agent,init,logger,errors,observability,types}.ts`. Spec: `docs/specs/grove-agent-spec.md` (729 lines). Its non-goals say "AI model selection stays in Lumen; GroveAgent provides plumbing." It contains **no agent loop** — no tool registry, budgets, or transcript. Only consumer: `workers/onboarding/src/agent.ts` (email-sequence DO, no LLM). So the new core would sit *beside/under* it: GroveAgent = DO shell (scheduling, state sync, WebSocket), new core = loop/tools/protocol. Must decide: does the core depend on Agents SDK or stay runtime-neutral and let GroveAgent adapt it?
2. **Mycelium's source is NOT in this repo.** Only refs: grove-router binding (`services/grove-router/src/index.ts:19,85`, wrangler.toml:44, origin `mycelium.*.workers.dev`), Heartwood `POST /session/validate-service` (`services/heartwood/src/routes/session.ts:671-700`, SERVICE_SECRET, fails closed), spec `docs/specs/mycelium-spec.md` (949 lines).
3. **Lumen has no streaming over the worker and no agent semantics.** Worker routes: `/health /inference /embed /moderate /transcribe` (`workers/lumen/src/index.ts`). `stream` exists only in in-process `LumenClient.stream()` (`libs/engine/src/lib/ai/lumen/client.ts:193`). RemoteLumenClient has run/embed/moderate/transcribe — no stream. An agent core on Workers talking via service binding will need either a `/inference/stream` route or non-streaming steps. **Real gap to resolve.**
4. **Tool calling in Lumen is single-turn passthrough**: caller supplies `tools`/`toolChoice`, gets `toolCalls` back, executes them itself (`types.ts:100-135, 630-696`; spec `docs/specs/lumen-tool-calling-spec.md`). Gaps for a loop: `LumenMessageRole = "system"|"user"|"assistant"` (`types.ts:32`) — **no `tool` role, no `tool_call_id`**, so tool results can't be fed back faithfully. Remote worker schema accepts `tools`/`tool_choice` and returns `tool_calls` (`remote.ts:44-65, 100-170`). Needs a types change in Lumen (or core sends tool results as user text — lossy).
5. **Forage's hand-rolled tool calling is NOT a loop** and doesn't use Lumen: it has its own `AIProvider` (`services/forage/src/providers/{openrouter,deepseek,types,tools}.ts`), forces one tool (`DRIVER_TOOL`, `SWARM_TOOL`) with `toolChoice`, parses once, falls back to JSON prompt parsing (`agents/driver.ts:40-130`). It's structured-output-via-tool-call, in a DO (`durable-object.ts`, 1098 lines, `MAX_BATCHES`). Only a comment references lumen-models.json (`providers/index.ts:47`). So "forage-style" = forced single tool call; real loops don't exist anywhere yet. Issues #1602 (hardcoded model IDs → Lumen registry) and #1600 (retire Together.ai direct) target this drift.
6. **Timeline/Curio is also single-shot**: `workers/timeline-sync/src/generator.ts` — gather GitHub commits → one `lumen.run({task:"summary"})` via `RemoteLumenClient` w/ service binding (`:207-225`), tenant BYOK OpenRouter key decrypted from `tenant_secrets` (envelope encryption `GROVE_KEK`, `secrets-manager.ts`) passed as `options.tenantApiKey`. Also `libs/curios/src/timeline/providers/openrouter.ts` (older direct path). Today's pass has no tools — making it agentic (fetch commits on demand, read prior summaries, decide to continue a multi-day task) is a genuine but modest agent use case. Issue #1530 "timeline scheduled job not running" (open) is a risk for using it as a spike.

## 1. Lumen (libs/engine/src/lib/ai/lumen)
- Tasks (`types.ts:18-26`): moderation, generation, summary, embedding, chat, image, code, transcription. **No TTS, no "decision" task.** Models in `libs/engine/src/lib/data/lumen-models.json`; `config.ts` MODELS/TASK_REGISTRY (primary + fallbackChain), costs, PROVIDERS (OpenRouter `zdr:true`, CF Workers AI). Current primaries: DeepSeek V4.1 Flash (gen/chat/summary/code), GPT-oss Safeguard (moderation), Perplexity Embed 0.6B (embedding), Claude Haiku 5.5 (image), Whisper (CF).
- Client API (`client.ts`): `run`, `stream`, `embed`, `moderate`, `transcribe`, `getQuotaStatus`, `getUsageHistory`, `healthCheck`. Factory `createLumenClientAuto(env)` tri-mode: service binding `LUMEN` → HTTP `LUMEN_URL+LUMEN_API_KEY` → in-process (`factory.ts`). Default URL `https://lumen.grove.place`.
- Worker auth: `X-API-Key` vs `env.LUMEN_API_KEY` (`workers/lumen/src/auth/middleware.ts`); own rate limit (`lib/rate-limit.ts`); `lib/warden-client.ts` fetches creds via Warden.
- Pipeline: PII scrub (`pipeline/preprocessor.ts`), Songbird injection guard Canary→Kestrel→Robin(future) (`songbird.ts`), postprocessor, fallback chain, quota. Per-request `options`: model, maxTokens, temperature, skipQuota, skipPiiScrub, tenantApiKey (BYOK), songbird, shutter(stub), mcp(stub), tools, toolChoice, metadata.
- Quota (`quota/limits.ts`, `tracker.ts`): **daily request counts per tier per task** (wanderer/seedling/sapling/…; tiers from `platform/config/tiers.ts`). Not token/cost budgets — an agent loop with N steps would burn N requests of quota; need a decision (skipQuota + core-side budget, or an `agent` task / per-run accounting).
- `mcp.ts` (123 lines): stub; `McpServerRegistry` works as a Map, `runMcpTools`/`injectMcpContext` throw. #471 (inject-context MCP) was **closed not_planned on 2026-11-10** when #1605 was filed → this stub is dead code the new core obsoletes (note AGENT.md: don't delete unasked; mention).
- Shutter (`shutter.ts`, `libs/shutter` Python+CF worker, `docs/specs/shutter-spec.md`): web-content distillation/injection defense; spec says Mycelium routes external web through Shutter. Natural *tool* for the core (fetch_url).
- Embeddings exist via Lumen `embed()`; no vector store/search yet (#1439 post search index, someday).

## 2. Warden (workers/warden)
Credential gateway: agents never see raw keys. Routes: `POST /nonce`, `POST /request` (service+action+params+tenant_id; `dualAuth` challenge-response or service binding; scope validation, rate limits, response scrubbing, audit log), `POST /resolve` (service-binding only), `/admin/agents`. Services registered: cloudflare, exa, github, openrouter, resend, stripe, tavily (`workers/warden/src/services/`). Client: `createWardenClient()` in engine. **Ideal tool-backend for the core**: `search` → Warden/tavily|exa, `github` → Warden/github. Enroll via `gw warden agent enroll`. Spec 1732 lines.

## 3. Mycelium (external repo; spec only here)
MCP server on Cloudflare `McpAgent` (Durable Object), Streamable HTTP `/mcp` + SSE `/sse`, OAuth via Heartwood (PKCE; `/authorize /callback /token`), bearer token forwarded to Lattice/Bloom/Amber/Rings/Meadow/Scout APIs, scopes (`mycelium-spec.md:461-615`), tools listed `:249-460`. Internal validation: Heartwood `/session/validate-service`. Relationship answer for #1605's open question: Mycelium = MCP **server** (tools out to external agents); core should be an MCP **client** able to consume Mycelium (or any MCP server) as one tool provider, but internal tools should call services directly via bindings. Roadmap lists Mycelium Phase 1-3 (`docs/plans/roadmap.md:70`).

## 4. Infra patterns to mirror/reuse
- **Loom** (`libs/loom`, `@autumnsgrove/loom` 0.1.1): `LoomDO` base (`base.ts`) — logger, `AlarmScheduler` (`alarm.ts`), `WebSocketManager`, `PromiseLockMap`, `SqlHelper`/`JsonStore` (`storage.ts`), declarative `routes()`, `schema()`, queue emit, workflow creation; adapters `sveltekit.ts`/`worker.ts`. Gen1 (blockConcurrencyWhile+SQL) and Gen2 lazy. Existing DOs in `services/durable-objects` (TenantDO, PostMetaDO, PostContentDO, SentinelDO, ExportDO, ThresholdDO; wrangler.toml has **no [[migrations]]** by design — see AGENT.md "Local durable objects"). Session-state DO for the core = natural LoomDO or GroveAgent (SQLite-backed).
- **Infra** (`libs/infra`, `@autumnsgrove/infra` 0.1.1): `GroveContext {db, storage, kv, services, scheduler, config, observer}`, `groveInfraMiddleware` (Hono) used by Lumen/Warden workers. Rule (AGENT.md): no raw `env.DB.prepare`.
- **Threshold** (`libs/engine/src/lib/platform/threshold`): `createThreshold`, stores DO/KV/D1 — per-tenant rate limits; tool calls should be rate-limited here.
- **Signpost** (`libs/engine/src/lib/errors`, plus `libs/grove-errors`): `GroveErrorDef`, `throwGroveError`, `buildErrorJson`; per-package catalogs (`GROVE-AGENT-XXX` exists in `libs/grove-agent/src/errors.ts`). A sibling repo can't import engine internals cheaply → decide whether core depends on `@autumnsgrove/lattice` or defines its own error catalog.
- **Thorn** (`libs/thorn`, engine `thorn/`): moderation, `moderate.ts`, hooks, behavioral; logs to `thorn_moderation_log`. Issue #1601 (Jev Router decision cascade) and #1624 (Songbird small decision models) — **these are the "decision model" use cases** parallel to Nova's `decide/` package; no decision API in Lumen yet.
- **Publishing**: all libs are `@autumnsgrove/*`, `publishConfig: {access: public, registry: npmjs}`, repository.directory field; engine at 1.2.2 (`libs/engine/package.json:763`), infra/loom 0.1.1. CI: `.github/workflows/{ci,deploy-*}.yml`, `_deploy-worker.yml`, `auto-tag.yml`. `gw` handles npm publishing + worktrees. grove-agent still points `main` at `./src/index.ts` (not built) — a standalone repo should ship built `dist` + exports map. Conventions: pnpm workspace, vitest, `tsc --noEmit` as `check`, tabs, Data Primacy/SDK Boundaries (AGENT.md), conventional commits, "Wanderer" terminology in user-facing text.

## 7. Open design questions surfaced by this exploration
- Lumen needs: streaming endpoint on worker; `tool` role/`tool_call_id` in message types; agent-run accounting (quota counts requests/day, not budgets); a "decision" task (typed questions → calibrated probabilities, à la Nova `decide`); possibly TTS.
- Dependency direction: core must not import Lattice internals if it lives in its own repo; Lumen is reached via HTTP (`RemoteLumenClient`-shaped contract) so core can define a tiny `Provider` interface and ship a Lumen adapter.
- GroveAgent coexistence (see §0.1).
- Where tool auth lives: Warden (service creds) + Heartwood session/service tokens + tenant BYOK (`tenant_secrets`).
- Workers limits for long loops (CPU/wall-clock/subrequest caps) — needs measurement; DO alarms + `agents` `schedule()` give resumability; CF Workflows used elsewhere (queen-firefly spec).
